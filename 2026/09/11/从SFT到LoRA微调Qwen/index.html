五、SFT 到底在优化什么

语言模型不是一次性预测整个 JSON，而是逐个预测下一个 token。假设目标输出是：

模型会依次学习预测：

设标准答案 token 序列为 (y_1, y_2, …, y_T)，模型对第 (t) 个 token 的预测概率为 (P_\theta(y_t | y_{<t}, x))。SFT 的交叉熵损失可以写成：

$$
\mathcal{L}{SFT} = - \sum{t=1}^{T} \log P_\theta(y_t | y_{<t}, x)
$$

其中 (x) 表示 system prompt 和用户请求。

若模型在“包裹签收但未收到”的样本上错误地倾向生成 refund，则 shipping 对应 token 的概率较低，loss 会增大。反向传播将调整 LoRA 参数，使模型在类似输入下更倾向输出 shipping。

七、什么是 LoRA

全参数微调会直接更新模型中的每一个权重。假设某个线性层的输入为 (x)，权重为 (W)，输出为：

$$
y = xW^T
$$

全量微调后，权重变成：

$$
W’ = W + \Delta W
$$

其中 (\Delta W) 与 (W) 一样大，需要训练大量参数。

LoRA（Low-Rank Adaptation）不直接训练完整的 (\Delta W)，而是假设有效更新可以由低秩矩阵近似：

$$
\Delta W = BA
$$

于是线性层变为：

$$
y = xW^T + \frac{\alpha}{r}x(BA)^T
$$

其中：

  1. (W) 是基础模型的原始权重，训练时被冻结；
  2. (A)、(B) 是 LoRA 新增的小矩阵，训练时更新；
  3. (r) 是低秩维度；
  4. (\alpha / r) 是缩放系数。

八、训练很少参数，为什么 LoRA 仍然有效

LoRA 训练参数少，不代表它影响很小。主要原因有以下三点。

1. 基础模型已经具备通用能力

Qwen 本来已经能理解中文、识别“退款”“签收”“扣款”等词，也具备生成 JSON 与客服语言的基础能力。

当前任务不是从零教模型学习语言，而是让它更稳定地完成特定映射：

这类任务通常不需要重写整个模型，只需调整模型调用已有知识时的偏好和输出概率。

2. 有效更新往往位于少数方向

全量微调允许 (\Delta W) 在所有方向上变化。LoRA 限制 (\Delta W = BA)，只能沿低秩空间的少数主要方向变化。

对于“将一个通用聊天模型适配为结构化客服分类器”这样的窄任务，这些方向往往已经足够。

当然，LoRA 也有边界。如果任务与基础模型差异极大、需要学习大量新领域知识，或低秩 (r) 设得过小，则可以提高 r、扩展目标层、增加数据，或者考虑全参数微调。

3. LoRA 分布在多层关键路径中

本项目并非只在输出层加入一个小分类器，而是在每一层 Transformer 的 Attention 和 MLP 中加入 LoRA。每层的小变化会逐层累积，最终能够明显改变输出 token 的概率分布。

因此，“训练参数只有 1.75%”描述的是参数数量，不等于“只影响 1.75% 的模型功能”。

九、Transformer Attention 原本如何计算

设一层 Transformer 的输入为 (X)，Attention 会先通过三组线性投影计算 Query、Key、Value：

$$
Q = XW_Q^T
$$

$$
K = XW_K^T
$$

$$
V = XW_V^T
$$

之后计算注意力权重：

$$
A = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)
$$

最后使用注意力权重加权 Value，并经过输出投影：

$$
O = AVW_O^T
$$

可以直观理解为：

部分 直观含义
Query（Q） 当前 token 想寻找什么信息
Key（K） 每个位置可以提供什么索引线索
Value（V） 每个位置实际携带的内容
QKT 当前 token 应该关注哪些位置
Output（O） 将注意到的信息写回模型主表示

当模型要输出：

它应该更关注用户请求中的“明天要用”“立即”“被盗”“重复扣款”等紧急线索。

$$

$$

不同投影层的改动可以这样理解：

1. q_proj：修改“当前 token 想找什么”

q_proj 决定 Query。LoRA 可以让模型在生成 urgency 时，更主动查询“明天”“马上”“紧急”“被盗”等线索。

2. k_proj：修改“什么信息更容易被注意到”

k_proj 决定 Key。LoRA 可以让“验证码”“无法登录”“账户被盗”等文本在生成 intent: account 时更容易成为注意力匹配的目标。

3. v_proj：修改“被取出的语义内容”

v_proj 决定 Value。即使模型已经注意到“支付成功但页面失败”，仍要决定从这段文字中提取哪些表示。LoRA 可以强化“支付异常”“避免重复支付”“需要优先处理”等语义。

4. o_proj：修改“注意力结果如何影响后续层”

o_proj 将多头 Attention 的结果写回残差流。对它加入 LoRA，会改变模型如何将注意到的上下文信息传递给后续 MLP、下一层 Attention 和最终的 token 预测。

因此 LoRA 对 Attention 的影响不是硬编码规则，而是通过调整 Q、K、V、O 的连续向量表示，使某些上下文线索在生成对应类别时更容易被利用。

十一、LoRA 还修改了 MLP

本项目的目标模块不止 Attention：

其中：

模块 所属部分 作用
q_proj、k_proj、v_proj、o_proj Attention 选择和聚合上下文信息
up_proj MLP 将隐藏表示扩展到更高维空间
gate_proj MLP 控制哪些特征被放大或抑制
down_proj MLP 将计算结果投影回隐藏维度

Qwen 的 MLP 可以粗略表示为：

$$
H = \text{activation}(XW_{up}^T) \odot \text{gate}(XW_{gate}^T)
$$

$$
Y = HW_{down}^T
$$

对 up_proj、gate_proj、down_proj 加 LoRA，意味着模型不仅改变“关注输入中的什么信息”，还改变“获得信息后如何加工、筛选和组合这些特征”。

因此，这个项目训练的不是一个额外接在最后的分类头，而是让 Transformer 每一层的 Attention 和 MLP 都发生轻量、分布式的任务适配。

十四、这个实验的局限与下一步

这个项目适合用来理解 SFT 和 LoRA，但它有明显局限：

  1. 训练数据只有 48 条，覆盖范围很窄；
  2. 验证集只有 12 条，统计结果波动较大；
  3. 模型可能主要学习了关键词，而不是真正复杂的客服推理；
  4. 没有奖励模型、强化学习或外部工具调用；
  5. 没有处理提示注入、错误数据、长期记忆等 Agent 问题。

十五、总结

本文的小项目展示了一个完整的参数高效微调流程：

其中最重要的几个结论是：

  1. SFT 的目标是提高标准答案 token 的条件概率；
  2. labels=-100 表示 prompt 仍可被模型看到，但不参与 loss；
  3. LoRA 冻结基础模型，仅训练低秩增量 (BA)；
  4. LoRA 参数虽然少，但分布在多层 Attention 和 MLP 的关键路径上，能够有效调整已有模型能力的调用方式；
  5. 对 Attention 而言，LoRA 修改了 Q、K、V、O 投影，使模型在生成答案时以不同方式选择、提取和传递上下文信息。
